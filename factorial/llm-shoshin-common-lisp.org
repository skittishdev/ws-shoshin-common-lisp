*Short answer:*  
No – Emacs does not run Common Lisp code natively.  The only way to use CL in an Emacs configuration is to start an external Common‑Lisp interpreter (CLISP, SBCL, ECL, etc.) and talk to it via an inferior process (e.g. SLIME/SLY).  You can’t mix Common‑Lisp syntax with Elisp syntax inside the same buffer or package.

*What you can do*

| What you want | How to get it | What you actually get |
|---------------|---------------|-----------------------|
| *Common‑Lisp‑style functions/macros in ELisp* | Use the =cl-lib= package (built‑in). | ELisp functions with CL naming (=cl-loop=, =cl-defun=, etc.). Syntax stays ELisp. |
| *Write a separate CL file and call it from ELisp* | Write a CL script, run it with =sbcl --script mycl.lisp=, or start an inferior CL process and send code via SLIME/SLY. | The CL code runs in its own process; you can pass data back and forth with =slime-eval=, =slime-require=, etc. |
| *Edit CL code in Emacs* | Use =clisp-mode=, =slime=, or =sly= which provide syntax highlighting, indentation, and evaluation. | Editing in Emacs, but evaluation happens in the external CL process. |
| *Use CL‑generated data in ELisp* | Have the CL program output JSON, XML, or Lisp objects and read them in ELisp with =json-read-file=, =xml-parse-file=, or =read=. | ELisp can consume the result, but the CL program is separate. |
| *Compile CL to native code for speed* | Compile with SBCL (=sbcl --script compile.lisp=) or ECL to an executable and call it from ELisp (=call-process=). | An external binary; no direct integration. |

*Why you can’t mix syntax*

- Emacs Lisp is interpreted by the =emacs= interpreter; it has its own reader and evaluator.  
- Common Lisp has a different reader, syntax (e.g. =defun= → =defun= but macros, =setf=, =dotimes=, etc.), and a separate compiler/interpreter.  
- The two readers are incompatible, so an Elisp buffer cannot contain unquoted CL syntax.  
- Emacs provides the =cl-lib= library to give you CL‑style utilities in ELisp, but that is only a compatibility layer, not a true Common‑Lisp environment.

*Bottom line*

If you need to write configuration logic in Common Lisp, split it into a separate CL file, run it in an external process (via SLIME/SLY, =call-process=, or =process-send-string=), and use its output in your Emacs config.  For everything that needs to run inside Emacs itself, stick to Emacs Lisp (or =cl-lib= for CL‑like helpers).
